# 修订记录

## 打包 — 合并为单一 skill
规范、安装器、目标定义、本记录收拢到一个自包含目录，可直接整体拷入 `~/.gal/skills/`：

```
skills/code-standards/
├── SKILL.md
├── CHANGELOG.md
├── scripts/install.py      安装器
├── scripts/targets.json    目标定义
└── resources/code-standards.md / .en.md   规范源
```

- `install.py` 按自身位置解析 `../resources`，目录整体移动不需要改路径
- 删除 `v2.1-slim` 对照版，v1.3 为唯一版本
- skill 名 `code-standards-install` → `code-standards`
- 默认语言改为英文：不加 `--lang` 即装英文版，中文需显式 `--lang zh`

## 更名 — agent-standards → code-standards
规范本身未改，只改标识与文件名，理由是 `agent-standards` 与 `AGENTS.md` 这个载体名过于接近，一个名叫 `agent-standards` 的块出现在 `AGENTS.md` 里读起来自我指涉；`code-standards` 也避免与「AI 代理」这一实现细节绑死。

- 源文件：`agent-standards.md` / `.en.md` → `code-standards.md` / `.en.md`
- marker：`<!-- BEGIN code-standards v… -->`；旧 marker 仍被识别，`--apply` 就地替换，不会追加第二块
- 安装目标：`.kiro/steering/code-standards.md`、`.cursor/rules/code-standards.mdc`、`.windsurf/rules/code-standards.md`
- 旧目标文件不自动删除，`--apply` 会在 stderr 提示手动清理
- 备份后缀：`.code-standards.bak`
- skill：`code-standards-install`

## v1.3（当前）— 合并 v2.1 的流程约束与 slim 版的实质条款
以 v1.1 为基底（保留 v1.2 对「推进与确认」的精简），补回 4 条流程约束：
- 单次提交只做一件事；标题写改了什么，正文写为什么
- MR 应以可独立评审为原则，过大时按可独立验证的单元拆分
- 破坏性变更必须在 MR 标注影响面与回滚方式
- 禁止未经评审直接改动主干；评审与必需检查由分支保护落实

从 v2.1-slim 补入 v1.1 缺失的实质条款：
- 避免在循环内逐条 I/O 或查询，优先批量处理（新增）
- 缓存必须定义失效策略；优化前先测量（并入分页条）
- 方案未定不动手，返工成本高于多花十分钟设计；探索性原型除外，须限定范围与时间（新增）
- 破坏性变更恢复方案明确为回滚／前向修复／备份恢复，按风险选择（原为笼统的"经评审的恢复方案"）

结果：49 → 55 条，2243 字符（英文 6347 字符 / 1142 词）；10 节不变。

## v1.1 — 按"能否改变本轮决策"审计后剪裁
判据分四级：A 改变模型动作 / B 改变交付内容形态 / C 只影响 MR 等人类流程产物 / D 仅为其他条款提供判据。

删除（C 级，移交基础设施，不属 prompt 职责）：
- 「MR 应以可独立评审为原则，过大时按可独立验证的单元拆分」→ MR 模板与评审 checklist
- 「破坏性变更必须在 MR 标注影响面与回滚方式」→ MR 模板固定栏目
- 「单次提交只做一件事；标题写改了什么，正文写为什么」→ commitlint

合并（B 级，压缩形态类条款）：
- 「长任务按里程碑交付」并入「大需求先给分步计划」
- 「未验证部分说明是哪部分」并入「结论区分四态」
- 「说明假设、取舍、未做部分」与「默认汇报结论与证据」合并为单条

改写（去掉"在 MR 说明"这类非模型动作）：
- 「确需删除死代码必须在 MR 说明原因」→「须在交付中说明原因」
- 「内部签名可自行调整并在 MR 说明」→「可自行调整，交付时说明」

结果：55 → 50 条，2189 → 2103 字符（英文版 6625 字符 / 50 条）；A 级条款全部保留。

保留的判据说明：「结论必须区分通过/失败/未执行/不适用」不属形态类，因为谎报完成本身是一个动作，它是本规范最想防的事。

## v1.0 — 发布版常驻 prompt
- 定位为常驻系统提示，10 节 / 55 条 / 约 2200 字符（不含空白）
- 新增术语表 6 条：关键路径、对外关键接口、破坏性变更、无界数据源、trivial、高风险操作

- 新增项目级例外机制：可在 AGENTS.md 声明不适用条目
